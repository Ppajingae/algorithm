# 1. 지금까지 알고리즘 선택 흐름

문제를 보면 우선:

```text
1. 입력 크기는 얼마인가?

2. 내가 지금 반복해서 하고 있는 작업은 무엇인가?

3. 모든 경우를 확인해야 하는가?

4. 같은 계산을 반복하고 있는가?

5. 그래프인가?

6. 최단거리인가?

7. 현재 선택을 확정해도 되는가?

8. 문제를 동일한 형태의 작은 문제로 나눌 수 있는가?

9. 모든 상태를 저장할 필요가 있는가?
```

를 생각해본다.

---

# 2. 빠른 알고리즘 판별표

```text
모든 경우를 확인해도 작다
→ 완전탐색

연결된 노드를 전부 탐색
→ DFS / BFS

가중치 없는 그래프의 최단거리
→ BFS

양수 가중치 그래프의 최단거리
→ Dijkstra

큰 문제가 같은 형태의 작은 문제
→ 재귀 / 분할정복

여러 경우가 같은 상태로 합쳐지고
최적 결과만 남길 수 있음
→ DP

현재 최선의 선택을 확정하고
과거로 돌아갈 필요가 없음
→ Greedy

반복해서 값을 검색
→ Map / Set 고려

정렬하면 현재 판단을 확정할 수 있음
→ Sorting + Greedy 등을 고려
```

| 문제 | 핵심 |

| 유연근무제 | 구현 / 시간 표현 변환 |

| 바탕화면 정리 | 최소/최대 경계만 저장 |

| 단속카메라 | Sorting + Greedy |

# 4. 특히 아직 익숙해져야 할 것

지금은 여러 알고리즘을 한 번씩 실제 문제에서 접하기 시작한 단계다.

따라서 당장 구현을 전부 외우기보다는:

```text
DFS
→ 깊게 탐색

BFS
→ 가까운 순서
→ 가중치 없는 최단거리

Dijkstra
→ 가중치 있는 최단거리

DP
→ 같은 상태의 결과를 압축해서 저장

Greedy
→ 현재 선택을 확정하고 앞으로 진행

Divide & Conquer
→ 문제를 같은 형태의 작은 문제로 분할
```

정도의 연결부터 확실하게 만드는 것이 중요하다.

# 5. 가장 중요한 습관

## 입력 크기부터 확인

```text
N = 100
→ N²도 가능할 수 있음

N = 10,000
→ N² 의심

N = 100,000
→ 보통 O(N), O(N log N) 방향 고민
```

---

## 내부 반복문이 무엇을 하는지 확인

```text
"이중 for문이다."
```

보다:

```text
"내부 for문에서 매번 뭘 찾고 있지?"
```

가 중요하다.

---

## 반복 검색인가?

```text
→ Map / Set
```

---

## 이미 계산한 값인가?

```text
→ DP / Memoization 가능성
```

---

## 정렬하면 이전 데이터를 버릴 수 있는가?

```text
→ Greedy 가능성
```

---

## 루프를 공식으로 바꿀 수 있는가?

```text
반복해서 +1 하는 대신
끝 위치를 바로 계산할 수 있는가?
```

덧칠 문제에서 나왔던 패턴.

---

## 모든 상태가 필요한가?

```text
boolean[]
Map
List
```

를 만들기 전에:

```text
경계 하나
최댓값 하나
최솟값 하나
현재 위치 하나
```

만으로 표현할 수 없는지 확인한다.

---

# 6. 현재 가장 중요한 목표

알고리즘 이름을 보고 코드를 외우는 것보다:

```text
문제 특징
    ↓
필요한 정보
    ↓
필요한 상태
    ↓
적합한 알고리즘 / 자료구조
```

순서로 연결하는 연습을 한다.

예를 들어:

```text
"이거 BFS 문제네."
```

보다:

```text
"모든 간선 비용이 1이고
 시작점에서 최소 이동 횟수가 필요하네.

 가까운 노드부터 방문하면
 처음 도착했을 때가 최단거리겠네.

 → BFS"
```

가 훨씬 중요하다.

마찬가지로:

```text
"이거 Greedy네."
```

보다:

```text
"진출점 순으로 정렬하면
 현재 카메라 위치를 확정할 수 있고
 처리한 차량은 다시 볼 필요가 없네.

 → Greedy"
```

까지 연결하는 것이 목표다.

# 한 장 요약

```text
[완전탐색]
전부 해본다.
→ 입력 크기 확인


[DFS]
깊게 탐색한다.
→ 연결 영역 / 그래프 탐색
→ 재귀 또는 Stack


[BFS]
가까운 순서로 탐색한다.
→ Queue
→ 가중치 없는 최단거리


[Dijkstra]
비용이 가장 작은 경로를 확장한다.
→ PriorityQueue
→ 양수 가중치 최단거리


[Recursion]
큰 문제를 같은 형태의 작은 문제로 표현한다.
→ 함수의 의미부터 정의


[Divide & Conquer]
현재 문제를 여러 개의 작은 동일 문제로 나눈다.
→ 쿼드압축


[DP]
같은 상태까지 오는 여러 결과 중
필요한 최적값만 기억한다.
→ 정수 삼각형


[Greedy]
현재 선택을 확정하고 앞으로 간다.
→ 그 선택이 전체 최적해를 깨지 않는 근거 필요
→ 단속카메라


[HashMap / Set]
반복 검색을 저장된 조회로 바꾼다.
→ 달리기 경주


[공통]
입력 크기 확인
→ 반복되는 작업 찾기
→ 불필요한 상태 제거
→ 현재 저장하는 값의 의미를 정의
```
