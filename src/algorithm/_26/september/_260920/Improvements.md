# Day 1 - 유연근무제

## 결과
- 풀이 성공
- 핵심 유형: 구현 / 날짜 계산 / 시간 계산
- 시간복잡도: O(N × 7) → 사실상 O(N)

---

## 좋았던 점

### 1. 문제의 조건을 코드로 직접 분리해서 구현함
- 직원별로 7일의 출근 기록을 순회하는 구조를 잡음.
- 주말(토/일)은 평가 대상에서 제외해야 한다는 조건을 별도로 처리함.
- 직원별 성공 여부를 `count`로 관리해서 최종 결과를 계산함.

### 2. HHMM 시간 표현의 문제를 발견하고 수정함
처음에는 다음처럼 단순 차이로 계산함.

`실제 출근 시간 - 희망 출근 시간 <= 10`

하지만 HHMM 형식은 분 단위 정수가 아니기 때문에 시간 경계를 넘어갈 때 문제가 발생함.

예:
- 희망 출근: 08:55 (`855`)
- 허용 출근: 09:05 (`905`)
- `905 - 855 = 50`
- 실제 시간 차이는 10분

이를 `parseTime()`을 만들어 시(hour)와 분(minute)을 분리한 뒤
10분을 더하고 60분을 넘으면 시간을 증가시키는 방식으로 해결함.

### 3. 직접 디버깅하면서 원인을 좁힘
`timeLogData`, `scheduleData`, `startDay`, `count` 등을 출력하면서
어느 조건에서 예상과 다른 결과가 나오는지 확인하는 방식으로 접근함.

---

## 개선할 점

### 1. 시간 계산을 위해 String으로 변환할 필요가 없음

현재 방식:

`855 → "855" → substring → 8 / 55`

정수 연산만으로 더 간단하게 처리할 수 있음.

- `time / 100` → 시
- `time % 100` → 분

예:
`855 / 100 = 8`
`855 % 100 = 55`

코테에서는 문자열 변환보다 숫자의 표현 규칙을 이용한 산술 연산을 먼저 생각해볼 것.

---

### 2. 실제 출근시간은 변환할 필요가 없음

현재는 실제 출근시간도 다음과 같이 처리함.

`parseTime(timeLogs[i][j], 0)`

하지만 실제 출근시간에는 아무 시간도 더하지 않기 때문에 원래 값과 동일함.

변환이 필요한 값은 `희망 출근시간 + 10분`뿐임.

불필요한 연산을 줄이고 "어떤 데이터를 왜 변환하는지"를 명확하게 할 것.

---

### 3. 입력값 `startDay`를 직접 변경하고 있음

현재 내부 반복문에서 `startDay++`를 수행함.

이 방식은 `startDay`가 모든 직원에게 공통으로 적용되는 시작 요일이라는 의미를 흐릴 수 있음.

특히 여러 직원의 데이터를 순회하면서 하나의 상태를 계속 변경하기 때문에
코드를 읽을 때 현재 `startDay`가 어떤 값을 가지고 있는지 추적하기 어려움.

가능하면 반복문의 인덱스 `j`와 최초 `startDay`를 이용해서
현재 요일을 계산하는 방식이 더 안전함.

핵심:
"계산할 수 있는 값은 상태로 관리하지 않는다."

---

### 4. 요일 변경과 출근 성공 조건이 결합되어 있음

현재 `startDay == 7` 처리 로직이 출근 성공 조건 내부에 존재함.

요일 순환은 날짜 계산의 책임이고,
출근 성공 여부는 출근시간 판정의 책임임.

두 로직을 분리하면 코드가 더 이해하기 쉬워짐.

---

### 5. `count == 7`이 꼭 필요한지 생각해볼 수 있음

실제 요구사항은:

"평일에 한 번이라도 지각하면 상품을 받을 수 없다."

따라서 모든 날짜의 성공 횟수를 세는 방식 외에도
평일 지각을 발견하는 순간 해당 직원을 실패 처리하는 방법을 생각할 수 있음.

코테에서는 문제를
"성공 횟수를 센다"
가 아니라
"실패 조건이 존재하는가?"
관점에서도 바라볼 것.

---

## 오늘의 핵심 실수

### HHMM을 일반 정수처럼 계산함

`855 + 10 != 905`

HHMM 형식에서는 100이 1시간이 아니라,
60분이 1시간이라는 점을 고려해야 함.

시간 데이터를 만났을 때는 먼저 다음을 확인할 것.

1. 단순 정수인가?
2. HHMM 표현인가?
3. 실제 분 단위로 변환하는 것이 편한가?
4. 시/분을 분리해서 계산하는 것이 편한가?

---

## 오늘 가져갈 포인트

> 데이터가 숫자로 주어진다고 해서 반드시 일반적인 정수처럼 계산할 수 있는 것은 아니다.

숫자가 무엇을 표현하는지 먼저 확인해야 한다.

그리고 반복문에서 값이 계속 변하는 코드가 나오면:

> "이 값을 정말 상태로 가지고 있어야 하나?
> 인덱스로 계산할 수 있지 않을까?"

를 한 번 생각해보기.
