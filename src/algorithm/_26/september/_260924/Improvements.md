# 2026-09-24 코딩테스트 복기 - 합승 택시 요금

## 문제

프로그래머스 - 합승 택시 요금

### 핵심 조건

- 지점 개수 `n ≤ 200`
- 간선은 양방향
- 각 간선마다 택시 요금이 존재
- `s`에서 A와 B가 같이 출발
- A의 목적지 = `a`
- B의 목적지 = `b`
- 중간까지 합승한 뒤 각자 이동 가능
- 합승하지 않는 것도 가능
- 전체 택시비의 최솟값을 구해야 함

---

# 처음 접근

처음에는 `fares`를 직접 따라가면서 경로를 구성하려고 했다.

대략적인 생각은 다음과 같았다.

```text
1. fares에서 현재 위치와 연결된 지점을 찾는다.
2. 다음 이동 지점을 결정한다.
3. 이동 비용을 누적한다.
4. A와 B의 경로가 겹치면 해당 비용은 한 번만 계산한다.
5. 최소 비용을 구한다.
```

처음 메모:

```java
// fares에 있는 0번째 값과 일치하는 s값을 찾고 이것에 맞는 이동경로 파악
// 이동경로 파악 후에 2번째 값으로 값 계산
// 이후 최소 비용 산출
// 가는 경로에 경로가 겹칠 경우 비용 1번만 구성
```

하지만 이 접근에는 몇 가지 문제가 있었다.

---

# 1. fares의 [0], [1]을 출발/도착으로 보면 안 된다

예를 들어:

```java
{4, 1, 10}
```

은

```text
4 → 1
```

만 가능한 것이 아니라

```text
4 ↔ 1
```

이다.

즉:

```java
fare[0] == current
```

만 검사하면 반대 방향의 간선을 놓치게 된다.

그래서 처음 그래프를 만들 때 양쪽 방향을 모두 등록했다.

```java
fareNodes.get(fare[0]).add(
    new Node(fare[1], fare[2])
);

fareNodes.get(fare[1]).add(
    new Node(fare[0], fare[2])
);
```

결과적으로:

```text
fareNodes.get(k)
```

만 확인하면 `k`와 연결된 모든 지점을 확인할 수 있게 된다.

---

# 2. ArrayList의 capacity와 size는 다르다

처음에는 다음과 같이 만들었다.

```java
ArrayList<Node> fareNodes = new ArrayList<>(n + 1);
```

그리고:

```java
fareNodes.get(4)
```

를 호출했더니:

```text
IndexOutOfBoundsException
```

이 발생했다.

원인은:

```java
new ArrayList<>(n + 1)
```

이 `size = n + 1`을 만드는 것이 아니기 때문이다.

이 값은 초기 `capacity`일 뿐이다.

즉:

```java
ArrayList<Node> list = new ArrayList<>(7);
```

이어도:

```text
capacity = 7
size = 0
```

이다.

그래프를 만들기 위해서는 실제 리스트를 넣어줘야 했다.

```java
ArrayList<ArrayList<Node>> fareNodes = new ArrayList<>();

for (int i = 0; i <= n; i++) {
    fareNodes.add(new ArrayList<>());
}
```

이후:

```text
0 → []
1 → []
2 → []
...
n → []
```

구조가 실제로 만들어진다.

---

# 3. 처음에는 실제 이동 경로를 알아야 한다고 생각했다

처음 사고는 다음과 비슷했다.

```text
S → ? → ? → A
S → ? → ? → B
```

두 경로를 직접 구하고:

```text
두 경로에서 겹치는 부분
```

을 찾아서 합승 요금을 계산하려고 했다.

이 때문에:

```text
현재 지점
이전 지점
다음 지점
```

등을 저장해야 하지 않을까 생각했다.

하지만 최종적으로 문제를 풀기 위해서는 **실제 경로 자체가 필요하지 않았다.**

필요한 것은:

```text
두 지점 사이의 최소 비용
```

뿐이었다.

---

# 4. 가장 중요했던 사고 전환

이번 문제에서 가장 어려웠던 부분.

처음에는:

```text
A와 B의 경로가 어디에서 겹치는가?
```

를 찾으려고 했다.

하지만 문제를 반대로 생각할 수 있었다.

> "두 사람이 k에서 헤어진다고 가정하면?"

그러면 전체 비용이 세 구간으로 정확하게 나뉜다.

```text
          ┌──── A
          │
S ─────── K
          │
          └──── B
```

필요한 비용은:

```text
S → K
K → A
K → B
```

이다.

따라서 `K`에서 헤어졌을 때 총비용은:

```text
cost(S → K)
+ cost(K → A)
+ cost(K → B)
```

가 된다.

이렇게 바꾸면서 문제에서 실제 경로를 추적할 필요가 사라졌다.

---

# 5. 헤어지는 지점을 직접 판별할 필요도 없다

처음에는 탐색 도중:

```text
"여기서 A와 B가 헤어져야 하나?"
```

를 판별해야 한다고 생각했다.

하지만 그럴 필요가 없다.

지점이 최대 `n = 200`개이므로 모든 지점을 헤어지는 지점이라고 가정하면 된다.

```java
for (int k = 1; k <= n; k++) {

}
```

각 `k`에 대해:

```text
S → K
K → A
K → B
```

의 최소비용을 더하고 그중 가장 작은 값을 선택한다.

즉:

```text
헤어지는 지점을 찾아낸다
```

가 아니라

```text
모든 지점을 헤어지는 지점으로 가정해서 비교한다
```

가 핵심이었다.

---

# 6. 왜 S에서 가장 가까운 지점을 선택하면 안 되는가

중간에 다음과 같은 접근을 했다.

```java
int shortestDistance = Integer.MAX_VALUE;
int nextCount = 0;

for (int k = 1; k <= n; k++) {
    if (result[k] < shortestDistance && result[k] != 0) {
        shortestDistance = result[k];
        nextCount = k;
    }
}
```

즉:

```text
S에서 가장 가까운 지점
```

을 먼저 선택하고 그 지점에서 다시 탐색하려고 했다.

하지만:

```text
S에서 가까운 지점
```

과

```text
합승을 종료하기 가장 좋은 지점
```

은 전혀 다른 개념이다.

예를 들어:

```text
S → 1 = 1
S → 2 = 10

1 → A = 100
1 → B = 100

2 → A = 1
2 → B = 1
```

이라면:

```text
K = 1
1 + 100 + 100
= 201
```

반면:

```text
K = 2
10 + 1 + 1
= 12
```

이다.

따라서 분기점은:

```text
S → K
```

만 보고 결정할 수 없다.

항상:

```text
S → K + K → A + K → B
```

전체 비용을 비교해야 한다.

---

# 7. 다익스트라 사용

문제는 결국 여러 지점 사이의:

```text
최소 이동 비용
```

이 필요했다.

모든 간선 비용은 양수이므로 다익스트라를 사용할 수 있다.

그래프:

```java
ArrayList<ArrayList<Node>> fareNodes
```

거리:

```java
int[] dist
```

우선순위 큐:

```java
PriorityQueue<Node> pq
```

를 사용했다.

다익스트라의 의미:

```text
start → 모든 지점까지의 최소비용
```

---

# 8. 다익스트라에서 모든 간선을 다시 보면 안 된다

중간에 다음과 같이 작성했다.

```java
for (ArrayList<Node> nodes : fareNodes) {
    for (Node next : nodes) {

    }
}
```

하지만 현재 정점이 `nowVertex`라면 필요한 것은:

```text
현재 정점에서 이동 가능한 간선
```

뿐이다.

이미 인접 리스트를 만들었으므로:

```java
for (Node next : fareNodes.get(nowVertex)) {

}
```

만 확인하면 된다.

이 부분에서 다시 확인한 원칙:

> 자료구조를 만들어놓고 그 자료구조의 장점을 사용하지 않으면 의미가 없다.

인접 리스트를 사용했다면 현재 정점의 인접 간선만 탐색한다.

---

# 9. dist 초기화 실수

처음에는:

```java
int[] dist = new int[n + 1];
```

만 사용했다.

하지만 Java의 `int[]` 기본값은:

```text
0
```

이다.

그러면:

```java
if (dist[next] > dist[current] + cost)
```

가 사실상:

```text
0 > 0 + cost
```

가 되어 갱신되지 않는다.

따라서:

```java
Arrays.fill(dist, INF);
dist[start] = 0;
```

으로 초기화해야 한다.

---

# 10. enhanced for문 실수

한 번은 다음과 같이 작성했다.

```java
for (int i : dist) {
    dist[i] = INF;
}
```

하지만:

```java
for (int i : dist)
```

에서 `i`는 배열의 인덱스가 아니라 **배열의 값**이다.

초기 `dist`가:

```text
[0, 0, 0, 0, 0, ...]
```

이면 `i`는 계속 `0`이다.

따라서 위 코드는 사실상:

```java
dist[0] = INF;
dist[0] = INF;
dist[0] = INF;
...
```

가 된다.

배열 전체를 동일한 값으로 초기화할 때는:

```java
Arrays.fill(dist, INF);
```

를 사용한다.

---

# 11. dist와 result를 혼용했던 문제

다익스트라를 메서드로 분리하면서:

```java
int[] result = dist.clone();
```

을 사용했다.

그런데 실제 계산은:

```java
result[next.index] = ...
```

에 저장하면서 PQ에는:

```java
dist[next.index]
```

를 넣거나 마지막에:

```java
return dist;
```

를 하는 실수가 있었다.

즉:

```text
초기 데이터 = dist
실제 계산 = result
PQ = dist
반환 = dist
```

처럼 서로 다른 배열을 섞어 사용했다.

다익스트라 내부에서는 어떤 배열을 거리 배열로 사용할 것인지 하나로 통일해야 한다.

수정 후:

```text
계산 → result
PQ → result
반환 → result
```

로 맞췄다.

---

# 12. 다익스트라는 3번이면 된다

헤어지는 지점 `K`에 대해 필요한 값:

```text
S → K
K → A
K → B
```

그래프가 양방향이므로:

```text
K → A = A → K
K → B = B → K
```

이다.

따라서 다익스트라를 모든 K에서 실행할 필요가 없다.

다음 세 번이면 된다.

```text
S → 모든 지점
A → 모든 지점
B → 모든 지점
```

결과를:

```java
int[] fromS;
int[] fromA;
int[] fromB;
```

라고 하면:

```text
fromS[k] = S → K
fromA[k] = A → K = K → A
fromB[k] = B → K = K → B
```

이다.

따라서:

```java
for (int k = 1; k <= n; k++) {
    cost = fromS[k]
         + fromA[k]
         + fromB[k];

    answer = Math.min(answer, cost);
}
```

형태로 모든 분기점을 검사할 수 있다.

# 13. 합승하지 않는 경우도 별도 처리할 필요가 없다

이것도 처음에는 별도로 처리해야 할 것처럼 보였다.

하지만:

```text
K = S
```

라고 생각하면:

```text
S → S = 0
S → A
S → B
```

가 된다.

따라서:

```text
0 + S → A + S → B
```

이고, 이것이 바로 처음부터 각자 택시를 타는 경우다.

즉 모든 `K`를 검사하면:

```text
합승
부분 합승
합승하지 않음
```

을 하나의 식으로 처리할 수 있다.

---

# 14. 경계조건 실수

처음에는:

```java
for (int k = 1; k < n; k++)
```

로 작성했다.

그러면 `n`번 지점을 검사하지 않는다.

하지만 `n`번 지점이 최적의 분기점일 수도 있다.

실제로 예제 #3은:

```text
n = 6
s = 4
a = 5
b = 6
```

이고 최적 경로는:

```text
4 → 6 합승
6에서 B 도착
6 → 5 A 이동
```

이다.

즉:

```text
K = 6
```

이 최적이다.

따라서:

```java
for (int k = 1; k <= n; k++)
```

로 검사해야 한다.

# 15. Integer.MAX_VALUE 사용 시 주의

현재 INF로:

```java
Integer.MAX_VALUE
```

를 사용했다.

문제 입력에서는 실제로 overflow 문제가 발생하지 않아 통과했지만 일반적인 최단거리 구현에서는 주의해야 한다.

예를 들어:

```java
Integer.MAX_VALUE + 10
```

은 int 범위를 넘어가면서 음수가 될 수 있다.

따라서 다음과 같은 방법을 고려할 수 있다.

### 방법 1

충분히 크지만 연산해도 overflow가 발생하지 않는 값을 INF로 사용한다.

```java
int INF = 1_000_000_000;
```

### 방법 2

`long`을 사용한다.

```java
long[] dist;
```

### 방법 3

INF인지 확인한 후 더한다.

```java
if (dist[current] != INF) {
    ...
}
```

최단거리 문제에서는:

> INF에 다른 값을 더할 가능성이 있는가?

를 확인한다.

# 16. Node 클래스 제출 오류

로컬에서는 별도 파일로 사용할 수 있었지만 프로그래머스 제출 시:

```java
public class Node
```

를 `Solution.java` 안에 같이 넣으면:

```text
class Node is public,
should be declared in a file named Node.java
```

컴파일 오류가 발생했다.

Java에서는 하나의 `.java` 파일에 여러 개의 `public` 최상위 클래스를 선언할 수 없다.

따라서:

```java
class Node implements Comparable<Node> {
}
```

처럼 `public`을 제거하거나:

```java
public class Solution {

    static class Node implements Comparable<Node> {

    }
}
```

처럼 내부 클래스로 만들 수 있다.

코딩테스트에서는 `static class Node` 방식도 편하다.

# 시간복잡도

다익스트라를 인접 리스트 + PriorityQueue로 구현했다.

다익스트라 한 번의 시간복잡도:

```text
O((V + E) log V)
```

일반적으로:

```text
O(E log V)
```

정도로 표현할 수 있다.

이번 문제에서는 다익스트라를 3번 실행한다.

```text
3 × O(E log V)
```

상수 3을 제거하면:

```text
O(E log V)
```

이다.

마지막 분기점 검사:

```java
for (int k = 1; k <= n; k++)
```

는:

```text
O(V)
```

이다.

따라서 전체:

```text
O(E log V)
```

수준이다.

---

# 최대 입력 기준 확인

```text
V = n ≤ 200
```

간선 최대:

```text
E ≤ n(n-1)/2

200 × 199 / 2
= 19,900
```

다익스트라 3번이므로 충분히 처리 가능한 크기다.

```java
dijkstra(...)
```

로 분리했다.

## 4. 디버깅하면서 자료구조의 의미를 확인했다

이번 문제에서 발생했던:

```text
ArrayList capacity / size
enhanced for의 value/index 차이
양방향 간선
dist/result 혼용
배열 초기값
경계조건
```

등을 직접 수정하면서 Java 자료구조와 그래프 구현도 같이 복습했다.

---

# 개선할 점

## 1. 실제 경로를 너무 일찍 추적하려고 했다

처음에는:

```text
어디로 이동하는가?
이전 위치는 어디인가?
A/B 경로가 어디에서 겹치는가?
```

를 생각했다.

하지만 문제에서 요구하는 결과는:

```text
최소 비용
```

이지:

```text
실제 이동 경로
```

가 아니다.

앞으로 최단거리 문제를 보면 먼저:

> 결과에 실제 경로가 필요한가, 아니면 거리만 필요한가?

를 확인한다.

경로가 필요 없다면 `previous` 등의 상태를 저장하지 않아도 된다.

---

## 2. "헤어지는 시점 판별"에 집중했다

처음에는:

```text
어떤 조건에서 A와 B가 헤어지는가?
```

를 찾으려고 했다.

하지만 후보가 `n ≤ 200`개밖에 없었다.

따라서:

```text
판별
```

하려고 복잡한 조건을 만드는 것보다:

```text
모든 후보를 가정하고 계산
```

하는 것이 훨씬 단순했다.

앞으로는:

> 후보 개수가 충분히 작다면 전부 후보로 놓고 비교할 수 없는가?

를 먼저 확인한다.

---

## 3. 부분 비용만 보고 다음 상태를 결정하려 했다

중간에:

```text
S에서 가장 가까운 지점
```

을 다음 지점으로 선택하려 했다.

하지만 최종 목표는:

```text
S → K
```

의 최소가 아니라:

```text
S → K + K → A + K → B
```

의 최소다.

즉 **부분적으로 가장 좋아 보이는 선택이 전체 최적해라는 보장은 없다.**

앞으로 greedy하게 하나를 선택하려면:

> 지금의 최선 선택이 전체 최적해를 보장하는 이유가 있는가?

를 확인한다.

근거가 없다면 모든 후보를 비교하거나 다른 알고리즘을 고려한다.

---

# 이번 문제에서 가장 중요한 사고 변화

처음:

```text
A의 경로를 찾는다.
B의 경로를 찾는다.
두 경로가 겹치는 곳을 찾는다.
겹친 비용을 한 번만 계산한다.
```

최종:

```text
헤어지는 지점 K를 하나 가정한다.

S → K 최소비용
K → A 최소비용
K → B 최소비용

세 값을 더한다.

모든 K를 확인한다.
```

이 변화가 이번 문제의 핵심이었다.

# 문제를 다시 만났을 때 생각할 순서

비슷한 문제를 다시 만나면 다음 순서로 생각한다.

```text
1. 문제를 그래프로 표현할 수 있는가?

2. 실제 경로가 필요한가?
   아니면 최소 비용만 필요한가?

3. 최종 답을 어떤 구간의 비용 합으로 분해할 수 있는가?

4. 결정해야 하는 중간 지점/상태가 있는가?

5. 그 후보 개수는 얼마나 되는가?

6. 후보를 모두 검사해도 되는가?

7. 각 후보마다 반복해서 필요한 계산은 무엇인가?

8. 그 계산을 미리 해둘 수 있는가?

9. 최단거리라면
   BFS / 다익스트라 / 플로이드-워셜 중
   입력 조건에 맞는 방법이 무엇인가?

10. 최종 시간복잡도가 제한사항에서 충분한가?
```

# 오늘의 핵심 교훈

> 복잡한 경로 자체를 찾으려고 하기 전에, 최종 답을 몇 개의 독립적인 비용으로 분해할 수 있는지 먼저 생각한다.

이번 문제에서는:

```text
전체 경로
```

를 직접 구성하려고 하면 복잡했지만:

```text
S → K
K → A
K → B
```

로 나누자 매우 단순해졌다.

그리고:

> "최적의 K를 어떻게 알아내지?"

라고 고민하기 전에 후보가 충분히 적다면:

```text
모든 K를 넣어보고 최소값을 구한다.
```

는 방법을 먼저 검토한다.

---

# 한 줄 복기

```text
실제 경로의 겹침을 추적하려 하지 말고,
합승 종료 지점 K를 모든 정점으로 가정한 뒤
S→K + K→A + K→B의 최소비용을 비교한다.
```

# 개인적으로 보완할 사고 패턴

이번 문제에서 부족했던 부분은 구현보다는 문제를 수식으로 단순화하는 단계였다.

처음부터:

```text
어떻게 이동하지?
```

에 집중하기보다 앞으로는 먼저:

```text
최종 answer는 어떤 값들의 합인가?
```

를 생각한다.

이번 문제라면:

```text
answer = min(
    dist(S, K)
    + dist(K, A)
    + dist(K, B)
)
```

이고:

```text
K = 1 ... n
```

이다.

즉 자연어 문제를 먼저 이런 형태로 바꾸는 연습이 필요하다.

```text
문제 설명
↓
상태 정의
↓
수식
↓
필요한 데이터
↓
알고리즘
↓
구현
```

이번에는 구현 능력보다 이 앞단의:

```text
상태 정의 → 수식화
```

가 가장 큰 연습 포인트였다.
