# 합승 택시 요금

## 문제 설명

밤늦게 귀가할 때 안전을 위해 항상 택시를 이용하던 `무지`는 최근 야근이 잦아져 택시비를 아낄 수 있는 방법을 고민하고 있습니다.

무지는 자신이 택시를 이용할 때 동료인 `어피치` 역시 자신과 비슷한 방향으로 가는 택시를 종종 이용하는 것을 알게 되었습니다.

두 사람의 귀가 방향이 비슷하기 때문에 택시 합승을 적절히 이용하면 택시요금을 절약할 수 있습니다.

두 사람이 같은 출발지 `s`에서 출발하여 각각:

```text
A → a
B → b
```

로 이동한다고 할 때, 두 사람이 목적지에 도착하기 위해 필요한 **최소 택시요금**을 구합니다.

---

# 이동 방식

두 사람은 처음부터 따로 이동할 수도 있고, 일정 지점까지 합승한 뒤 각자의 목적지로 이동할 수도 있습니다.

예를 들어:

```text
출발지 s
   |
   | 합승
   |
   v
   k
  / \
 /   \
v     v
a     b
```

와 같은 형태의 이동이 가능합니다.

`k`는 두 사람이 택시를 함께 이용하다가 헤어지는 지점이라고 볼 수 있습니다.

또한 합승하지 않는 것이 더 저렴하다면 처음부터 각자 이동해도 됩니다.

---

# 예시

다음과 같은 조건이 있다고 가정합니다.

```text
n = 6
s = 4
a = 6
b = 2
```

두 사람은 `4`번 지점에서 출발합니다.

```text
A의 목적지 = 6
B의 목적지 = 2
```

다음과 같이 이동할 수 있습니다.

```text
4 → 1 → 5
```

이 구간은 두 사람이 합승합니다.

요금:

```text
10 + 24 = 34
```

이후 `5`번 지점에서 두 사람이 헤어집니다.

A:

```text
5 → 6
```

요금:

```text
2
```

B:

```text
5 → 3 → 2
```

요금:

```text
24 + 22 = 46
```

따라서 총 요금은:

```text
34 + 2 + 46
= 82
```

입니다.

---

# 문제

다음 값들이 주어집니다.

```text
n     : 지점의 개수
s     : 출발 지점
a     : A의 도착 지점
b     : B의 도착 지점
fares : 지점 사이의 택시요금
```

두 사람이 `s`에서 출발하여 각각 `a`, `b`까지 이동할 때 필요한 **최저 예상 택시요금**을 반환합니다.

---

# fares

`fares`의 각 원소는 다음과 같습니다.

```text
[c, d, f]
```

의미:

```text
c ↔ d 이동 가능
택시요금 = f
```

예를 들어:

```text
[4, 1, 10]
```

이라면:

```text
4 → 1 = 10
1 → 4 = 10
```

입니다.

즉 이 문제의 간선은 **양방향**입니다.

---

# 제한사항

## 지점

```text
3 ≤ n ≤ 200
```

`s`, `a`, `b`는:

```text
1 ≤ s, a, b ≤ n
```

이며 서로 다른 값입니다.

---

## fares

```text
2 ≤ fares.length ≤ n × (n - 1) / 2
```

각 원소:

```text
[c, d, f]
```

에서:

```text
1 ≤ c, d ≤ n
1 ≤ f ≤ 100,000
```

입니다.

같은 두 지점 사이의 요금은 한 번만 주어집니다.

따라서:

```text
[c, d, f]
```

가 존재하면:

```text
[d, c, f]
```

는 별도로 주어지지 않습니다.

하지만 실제 이동은:

```text
c ↔ d
```

양방향으로 가능합니다.

출발지 `s`에서 목적지 `a`, `b`로 이동할 수 있는 경로가 존재하는 입력만 주어집니다.

# 문제에서 먼저 확인할 점

## 1. 그래프 문제

지점:

```text
1 ~ n
```

은 그래프의 `정점(Vertex)`으로 볼 수 있습니다.

`fares`:

```text
[c, d, f]
```

는:

```text
c ↔ d
```

를 연결하는 `간선(Edge)`이고 `f`는 간선의 가중치입니다.

즉 문제를 그래프로 표현하면:

```text
정점 = 지점
간선 = 택시 이동 경로
가중치 = 택시요금
```

입니다.

---

## 2. 양방향 그래프

문제에서:

```text
4 → 1
```

과:

```text
1 → 4
```

의 요금이 동일하다고 명시되어 있습니다.

따라서:

```text
무방향 가중치 그래프
```

입니다.

---

## 3. 단순히 s → a, s → b만 구하면 되는가?

합승이 없다면:

```text
s → a
+
s → b
```

의 비용을 계산하면 됩니다.

하지만 합승이 존재할 수 있습니다.

예를 들어:

```text
       ┌→ a
s → k ┤
       └→ b
```

처럼 중간 지점 `k`까지 함께 이동한 후 갈라질 수도 있습니다.

따라서 단순히:

```text
s → a 최단거리
s → b 최단거리
```

두 개만 계산해서는 합승에 의한 비용 절감을 제대로 반영할 수 없습니다.

# 직접 생각해볼 핵심 질문

이번 문제에서는 다음 질문들을 먼저 생각해봅니다.

```text
1. 두 사람이 어디까지 같이 갈 것인가?

2. 두 사람이 헤어지는 지점을 어떻게 정할 것인가?

3. 헤어지는 지점 후보는 몇 개인가?

4. 특정 지점 k에서 헤어진다고 가정하면
   필요한 비용은 어떤 구간들로 나눌 수 있는가?

5. 같은 지점 사이의 최단거리를
   여러 번 계산하게 되지는 않는가?

6. n이 최대 200이라는 조건을
   어떻게 활용할 수 있는가?
```

# 작은 예제로 생각하기

다음 그래프가 있다고 생각해봅니다.

```text
        2
       / \
      /   \
     1     4
      \   /
       \ /
        3
```

두 사람이:

```text
s = 1
a = 2
b = 4
```

라고 했을 때 가능한 선택은 여러 개입니다.

### 선택 1

처음부터 각자 이동:

```text
1 → 2

1 → ... → 4
```

### 선택 2

중간까지 합승:

```text
1 → 3
```

이후:

```text
3 → 2
3 → 4
```

### 선택 3

다른 지점까지 합승:

```text
1 → k
```

이후:

```text
k → a
k → b
```

이런 식으로 **어디에서 갈라질 것인지**에 따라 전체 비용이 달라집니다.

# 입력 크기 확인

```text
n ≤ 200
```

입니다.

정점 수가 수십만 개가 아니라 최대 `200`개라는 점을 확인할 필요가 있습니다.

반면 간선은 최대:

```text
n × (n - 1) / 2
```

이므로 `n = 200`일 경우:

```text
200 × 199 / 2
= 19,900
```

개까지 존재할 수 있습니다.

그래프가 상당히 촘촘할 수도 있습니다.

# 정확성 + 효율성 테스트

문제에 다음 문구가 있습니다.

```text
[본 문제는 정확성과 효율성 테스트 각각 점수가 있는 문제입니다.]
```

따라서 단순히 정답이 나오는 것뿐만 아니라 입력 크기가 커졌을 때의 성능도 고려해야 합니다.

특히 풀이 중:

```text
모든 경로를 직접 생성
```

하거나:

```text
같은 최단거리를 계속 처음부터 다시 계산
```

하는 구조가 생긴다면 시간복잡도를 확인해볼 필요가 있습니다.

# 이번 문제의 연습 포인트

최근 문제에서는:

```text
달리기 경주
→ 반복 탐색 제거

바탕화면 정리
→ 필요한 최소/최대 상태만 유지

덧칠
→ 여러 상태를 경계 하나로 축약
```

를 연습했습니다.

이번 문제에서는 한 단계 더 나아가:

```text

```

를 특히 신경 써봅니다.

아직 풀이 알고리즘을 정하지 말고 먼저:

> 합승이 끝나는 지점 하나를 정했다고 가정하면 총 요금을 어떤 세 구간의 비용으로 나눌 수 있을까?

부터 생각해보면 좋습니다.
