# 바탕화면 정리

## 문제 설명

코딩테스트를 준비하는 머쓱이는 프로그래머스에서 문제를 풀고, 나중에 다시 코드를 보면서 공부하려고 작성한 코드를 컴퓨터 바탕화면의 아무 위치에나 저장해 둡니다.

저장한 코드가 많아지면서 바탕화면이 너무 지저분해졌고, 프로그래머스에서 작성했던 코드는 해당 문제에서 다시 볼 수 있기 때문에 저장해 둔 파일들을 전부 삭제하기로 했습니다.

컴퓨터 바탕화면은 각 칸이 정사각형인 **격자판**입니다.

바탕화면의 상태를 나타내는 문자열 배열 `wallpaper`가 주어집니다.

- 빈칸: `.`
- 파일이 있는 칸: `#`

바탕화면의 격자점은 가장 왼쪽 위를 `(0, 0)`으로 하며 다음과 같이 표현합니다.

```text
(세로 좌표, 가로 좌표)
```

파일들은 격자점이 아니라 **격자칸 내부에 위치**합니다.

---

## 드래그

드래그는 격자점 S(`lux`, `luy`)에서 시작하여 격자점 E(`rdx`, `rdy`)에서 끝납니다.

```text
S(lux, luy)
        ↓
        ↓ drag
        ↓
E(rdx, rdy)
```

S와 E를 각각 직사각형의 **왼쪽 위**, **오른쪽 아래**로 하는 영역 내부의 모든 파일이 선택됩니다.

드래그 거리는 다음과 같이 계산합니다.

```text
|rdx - lux| + |rdy - luy|
```

모든 파일을 한 번에 선택하면서 **드래그 이동거리가 최소**가 되도록 해야 합니다.

최종적으로 다음 값을 반환합니다.

```text
[lux, luy, rdx, rdy]
```

---

## 예시

```text
wallpaper = [
    ".#...",
    "..#..",
    "...#."
]
```

파일의 위치는 다음과 같습니다.

```text
.#...
..#..
...#.
```

각 파일의 좌표는:

```text
(0, 1)
(1, 2)
(2, 3)
```

모든 파일을 포함하는 가장 작은 직사각형은 다음 범위를 가집니다.

```text
왼쪽 위  : (0, 1)
오른쪽 아래: (3, 4)
```

따라서:

```text
S = (0, 1)
E = (3, 4)
```

드래그 거리는:

```text
(3 - 0) + (4 - 1)
= 3 + 3
= 6
```

결과:

```text
[0, 1, 3, 4]
```

---

## 제한사항

- `1 ≤ wallpaper.length ≤ 50`
- `1 ≤ wallpaper[i].length() ≤ 50`
- `wallpaper`의 모든 원소의 길이는 동일합니다.
- `wallpaper[i][j]`는 바탕화면에서 `i + 1`행 `j + 1`열에 해당하는 칸의 상태를 나타냅니다.
- 각 칸은 `#` 또는 `.`만 가집니다.
- 바탕화면에는 적어도 하나의 파일이 존재합니다.
- 드래그 시작점과 끝점은 다음 조건을 만족합니다.

```text
lux < rdx
luy < rdy
```

| `["..", "#."]` | `[1, 0, 2, 1]` |

# 문제 핵심

모든 파일 `#`을 포함하는 **가장 작은 직사각형**을 찾는 문제입니다.

각 파일의 위치를 `(row, column)`이라고 했을 때 필요한 값은 네 개입니다.

```text
가장 위에 있는 파일의 row
가장 왼쪽에 있는 파일의 column

가장 아래에 있는 파일의 row
가장 오른쪽에 있는 파일의 column
```

이를 드래그 좌표와 연결하면:

```text
lux = 가장 작은 row
luy = 가장 작은 column

rdx = 가장 큰 row + 1
rdy = 가장 큰 column + 1
```

`+1`이 필요한 이유는 파일의 좌표가 **격자칸의 위치**를 나타내지만, 드래그 시작점과 끝점은 **격자점의 좌표**이기 때문입니다.

예를 들어 파일 하나가:

```text
(1, 0)
```

에 있다면 해당 파일이 차지하는 칸은:

```text
왼쪽 위 격자점  = (1, 0)
오른쪽 아래 격자점 = (2, 1)
```

입니다.

따라서 파일 좌표의 최댓값을 그대로 사용하는 것이 아니라 오른쪽 아래 영역까지 포함하기 위해 `+1`이 필요합니다.

# 풀이에서 생각할 포인트

## 1. 모든 파일의 좌표를 저장할 필요가 있는가?

최종적으로 필요한 값은:

```text
minRow
minColumn
maxRow
maxColumn
```

네 개뿐입니다.

따라서 모든 `#`의 위치를 `List` 등에 저장한 뒤 다시 최소/최대를 구할 필요 없이, 바탕화면을 탐색하면서 바로 갱신할 수 있습니다.

```text
# 발견

row 최소값 갱신
row 최대값 갱신
column 최소값 갱신
column 최대값 갱신
```

즉 이전에 확인한 파일들의 전체 좌표를 기억할 필요 없이 **현재까지의 최소/최대 정보만 유지**하면 됩니다.

---

## 2. String은 배열이 아님

`wallpaper`는:

```java
String[] wallpaper
```

이므로 바깥쪽은 배열이지만 각각의 행은 `String` 객체입니다.

따라서:

```java
wallpaper[i][j]
```

처럼 접근할 수 없습니다.

문자 하나를 가져오려면:

```java
wallpaper[i].charAt(j)
```

를 사용할 수 있습니다.

또는:

```java
char[] row = wallpaper[i].toCharArray();
```

처럼 문자 배열로 변환해서 탐색할 수도 있습니다.

---

## 3. 입력 크기

최대 크기는:

```text
50 × 50
```

이므로 전체 칸의 개수는 최대:

```text
2,500
```

입니다.

따라서 모든 칸을 한 번 확인하는 방식으로 충분합니다.

시간복잡도:

```text
O(H × W)
```

- `H`: wallpaper의 높이
- `W`: wallpaper의 너비

최대 2,500개의 칸만 검사하므로 성능상 문제가 없습니다.

# 이 문제에서 가져갈 포인트

> 모든 데이터를 저장해야 하는지 먼저 생각해본다.

최종 결과를 만들기 위해 필요한 정보가 최소값과 최대값뿐이라면 전체 데이터를 저장하지 않고 탐색하면서 필요한 상태만 유지할 수 있습니다.

또한 격자 문제에서는 다음을 구분해야 합니다.

```text
격자칸의 좌표
vs
격자점의 좌표
```

이번 문제에서는 파일은 `격자칸`에 존재하지만 드래그는 `격자점` 사이에서 이루어집니다.

따라서 오른쪽 아래 좌표를 구할 때:

```text
maxRow + 1
maxColumn + 1
```

이 필요하다는 점이 핵심입니다.
