# 하노이의 탑

## 문제 설명

하노이 탑(Tower of Hanoi)은 퍼즐의 일종입니다.

세 개의 기둥과 이 기둥에 꽂을 수 있는 크기가 다양한 원판들이 있습니다.

퍼즐을 시작하기 전에는 한 기둥에 원판들이 **작은 것이 위에 있도록 순서대로** 쌓여 있습니다.

게임의 목적은 다음 두 가지 조건을 만족시키면서 한 기둥에 꽂힌 원판들을 그 순서 그대로 다른 기둥으로 옮겨 다시 쌓는 것입니다.

### 이동 조건

1. 한 번에 하나의 원판만 옮길 수 있습니다.
2. 큰 원판이 작은 원판 위에 있어서는 안 됩니다.

---

## 기둥

하노이 탑에는 총 3개의 기둥이 있습니다.

```text
1번 기둥
2번 기둥
3번 기둥
```

처음에는 `1번 기둥`에 `n`개의 원판이 쌓여 있습니다.

목표는 모든 원판을:

```text
1번 기둥
    ↓
3번 기둥
```

으로 옮기는 것입니다.

이때 **최소 횟수로 이동**해야 합니다.

---

## 문제

1번 기둥에 있는 원판의 개수 `n`이 매개변수로 주어집니다.

`n`개의 원판을 1번 기둥에서 3번 기둥으로 최소 횟수로 옮기는 방법을 구하여 반환하는 `solution` 함수를 완성합니다.

각 이동은 다음과 같이 표현합니다.

```text
[출발 기둥, 도착 기둥]
```

예를 들어:

```text
[1, 2]
```

는:

```text
1번 기둥 → 2번 기둥
```

으로 원판 하나를 이동했다는 의미입니다.

---

# 제한사항

```text
1 ≤ n ≤ 15
```

---

# 입출력 예

| n | result |
|---|---|
| 2 | `[[1,2], [1,3], [2,3]]` |

---

# 입출력 예 설명

## n = 2

처음 상태를 다음과 같이 생각할 수 있습니다.

```text
1번       2번       3번

작은 원판
큰 원판
```

목표는 두 원판을 모두 `3번 기둥`으로 옮기는 것입니다.

### 1번째 이동

작은 원판을:

```text
1 → 2
```

로 이동합니다.

```text
[1, 2]
```

---

### 2번째 이동

큰 원판을:

```text
1 → 3
```

으로 이동합니다.

```text
[1, 3]
```

---

### 3번째 이동

작은 원판을:

```text
2 → 3
```

으로 이동합니다.

```text
[2, 3]
```

---

따라서 결과는:

```text
[
    [1, 2],
    [1, 3],
    [2, 3]
]
```

입니다.

---

# 문제를 풀기 전에 생각해볼 점

이번 문제에서는 바로 구현하기 전에 작은 `n`부터 직접 생각해봅니다.

## n = 1

원판이 하나라면:

```text
1 → 3
```

한 번이면 끝납니다.

```text
[[1, 3]]
```

---

## n = 2

```text
1 → 2
1 → 3
2 → 3
```

총 3번입니다.

---

## n = 3

가장 큰 원판을 `1번 → 3번`으로 옮기려면 그 원판 위에 있는 두 개의 원판이 먼저 없어져야 합니다.

즉 가장 큰 원판을 움직이기 직전에는:

```text
1번       2번       3번

큰 원판    나머지 2개
```

와 같은 상태가 되어야 합니다.

그다음:

```text
가장 큰 원판
1 → 3
```

으로 이동할 수 있습니다.

그리고 `2번 기둥`에 있는 나머지 원판들을 다시 `3번 기둥`으로 옮겨야 합니다.

---

# 이번 문제에서 생각할 질문

```text
1. n개의 원판을 옮기기 위해
   n-1개의 원판을 먼저 어떻게 처리해야 하는가?

2. 가장 큰 원판을 언제 이동할 수 있는가?

3. 가장 큰 원판을 이동한 이후
   나머지 n-1개의 원판은 어떻게 처리해야 하는가?

4. n개의 원판을 옮기는 과정 안에
   n-1개의 원판을 옮기는 동일한 문제가 반복되고 있지 않은가?

5. 원판이 1개만 남았을 때는 어떻게 되는가?

6. 함수의 매개변수로 단순히 n만 필요한가?
   아니면 출발 기둥, 도착 기둥 등의 정보도 필요할까?
```

---

# 작은 문제와 큰 문제의 관계 관찰하기

`n = 1`을 해결하는 방법을 알고 있다고 가정합니다.

그러면 `n = 2`를 해결할 때 `n = 1` 문제를 이용할 수 있는지 생각해봅니다.

마찬가지로:

```text
n = 3
```

을 해결할 때:

```text
n = 2
```

문제를 이용할 수 있는지 확인합니다.

즉:

```text
n = 1
↓
n = 2
↓
n = 3
↓
n = 4
...
```

에서 동일한 형태의 작업이 반복되는지 관찰하는 것이 중요합니다.

---

# 입력 크기 확인

최대:

```text
n = 15
```

입니다.

이번 문제에서는 단순히 `n = 15`라는 숫자만 보는 것보다:

```text
n이 1 증가할 때 필요한 이동 횟수가 어떻게 증가하는가?
```

를 확인해보는 것도 중요합니다.

예를 들어:

```text
n = 1 → ?
n = 2 → 3
n = 3 → ?
n = 4 → ?
```

처럼 직접 계산해보면서 규칙을 찾아볼 수 있습니다.

# 오늘의 연습 포인트

이번 문제에서는 특히 다음 부분을 신경 써봅니다.

```text
큰 문제를 그대로 해결하려 하지 않고
같은 형태의 더 작은 문제로 나눌 수 있는가?
```

그리고 구현 전에:

```text
n개의 원판을 A에서 C로 옮긴다
```

라는 작업을 더 작은 작업들로 분해해봅니다.

이번에도 바로 정답 코드를 작성하기보다 `n = 1`, `n = 2`, `n = 3`을 손으로 직접 옮겨보면서 반복되는 패턴부터 찾아보는 것이 핵심입니다.
