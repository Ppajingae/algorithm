# 알고리즘 풀이 정리 — 단어 변환

- 날짜: 2026-10-08
- 플랫폼: 프로그래머스
- 난이도: Level 3
- 알고리즘: BFS (너비 우선 탐색)
- 결과: 통과

## 1. 문제 요약

시작 단어 `begin`을 목표 단어 `target`으로 변환하는 최소 횟수를 구한다.

### 변환 조건

1. 한 번에 알파벳 하나만 변경할 수 있다.
2. 변환한 단어는 반드시 `words` 배열에 존재해야 한다.
3. `words` 배열의 순서는 변환 순서와 관계없다.
4. 목표 단어로 변환할 수 없다면 `0`을 반환한다.

### 예제

```java
String begin = "hit";
String target = "cog";
String[] words = {"hot", "dot", "dog", "lot", "log", "cog"};

// 정답: 4
```

변환 경로:

```text
hit → hot → dot → dog → cog
```

## 2. BFS를 선택한 이유

문제의 목표는 단순히 `target`에 도달하는 것이 아니라
**최소 변환 횟수**를 구하는 것이다.

### DFS

- 한 경로를 끝까지 탐색한다.
- 최소 변환 횟수를 구하려면 다른 경로도 비교해야 한다.
- 방문 처리와 경로 관리에 주의해야 한다.

### BFS

- 변환 횟수가 적은 경로부터 탐색한다.
- 한 번 변환으로 도달할 수 있는 단어를 먼저 확인한다.
- 처음 `target`에 도달했을 때 최소 변환 횟수를 보장한다.

따라서 BFS가 적합하다.

## 3. 그래프 구성 방식

일반적인 그래프 문제는 인접 리스트가 주어지거나
간선 정보로 인접 리스트를 구성한다.

하지만 이번 문제는 연결 관계가 직접 주어지지 않는다.

두 단어를 비교하여 **같은 위치에서 정확히 한 글자만 다르면**
서로 연결된 노드로 판단한다.

```text
hit → hot : 가능
hot → dot : 가능
hot → lot : 가능
hit → dot : 불가능
```

즉, 문자열 비교 로직이 인접 노드를 찾는 역할을 한다.

## 4. 구현 과정에서 헷갈렸던 부분

### 4.1. words 배열 순서대로 탐색하려 했던 문제

처음에는 `index++`를 이용하여 배열의 다음 단어를 선택하려 했다.

하지만 배열의 순서는 변환 경로와 관계없다.

올바른 접근은 현재 단어를 기준으로 `words` 전체를 확인하고,
변환 가능한 단어를 찾는 것이다.

### 4.2. break로 하나의 단어만 선택했던 문제

```java
for (String s : list) {
    if (canConvert(poll.word, s) && !visited.contains(s)) {
        visited.add(s);
        q.offer(new Node(poll.count + 1, s));
        break; // 문제 발생
    }
}
```

`break`가 존재하면 가장 먼저 발견한 단어만 큐에 들어간다.

예를 들어:

```text
hot
 ├─ dot
 └─ lot
```

`dot`과 `lot`이 모두 변환 가능한데도
`dot`만 탐색하게 될 수 있다.

BFS에서는 이동 가능한 모든 후보를 큐에 추가해야 한다.

### 4.3. 변환 횟수를 전역 변수로 관리했던 문제

처음에는 `while` 반복문에서 `count++`를 수행했다.

하지만 큐에서 단어를 꺼낸 횟수와 변환 횟수는 다르다.

```text
hit (0)
 └─ hot (1)
     ├─ dot (2)
     └─ lot (2)
```

`dot`과 `lot`은 각각 큐에서 꺼내지만
두 단어의 변환 횟수는 모두 2이다.

따라서 각 노드가 자신의 변환 횟수를 관리해야 한다.

```java
q.offer(new Node(poll.count + 1, s));
```

### 4.4. 문자열 비교 방식을 잘못 이해했던 문제

처음에는 이중 반복문으로 두 문자열에
동일한 알파벳이 존재하는지 비교했다.

하지만 문제에서 허용하는 것은
알파벳의 위치를 바꾸는 것이 아니라
**특정 위치의 알파벳 하나를 변경하는 것**이다.

```text
abc → adc : 가능 (1글자 변경)
abc → bac : 불가능 (2글자 변경 필요)
```

따라서 같은 인덱스의 문자를 비교해야 한다.

```java
private boolean canConvert(String current, String next) {
    int diff = 0;

    for (int i = 0; i < current.length(); i++) {
        if (current.charAt(i) != next.charAt(i)) {
            diff++;
        }
    }

    return diff == 1;
}
```

### 4.5. 방문 처리 시점

방문 여부는 `Set<String>`으로 관리한다.

```java
visited.add(s);
q.offer(new Node(poll.count + 1, s));
```

방문 처리를 큐에 추가하는 시점에 수행하면
같은 단어가 중복으로 큐에 들어가는 것을 방지할 수 있다.

## 5. 시간 복잡도

- N: words 배열의 단어 개수
- L: 단어의 길이

각 단어는 최대 한 번 큐에 들어간다.

큐에서 단어를 꺼낼 때마다
최대 N개의 단어와 비교한다.

두 단어를 비교하는 데 O(L)이 필요하다.

따라서:

- 시간 복잡도: O(N² × L)
- 공간 복잡도: O(N)

## 6. 핵심 정리

1. 최소 이동 횟수를 구하는 문제에서는 BFS를 고려한다.
2. BFS는 현재 노드에서 이동 가능한 모든 노드를 탐색해야 한다.
3. 배열 순서와 그래프 탐색 순서는 다르다.
4. BFS의 이동 횟수는 반복문 실행 횟수와 다르다.
5. 각 노드에 거리 정보를 저장하면 변환 횟수를 관리할 수 있다.
6. 방문 처리는 큐에 추가하는 시점에 수행하는 것이 효율적이다.
7. 문자열 변환 문제에서는 문자 포함 여부가 아니라 위치별 차이를 확인해야 한다.

## 7. 이번 문제에서 배운 점

기존 BFS 문제에서는 그래프의 연결 관계가 주어졌지만,
이번 문제에서는 연결 관계를 직접 판단해야 했다.

BFS의 기본 구조는 동일하다.

```text
현재 노드 꺼내기
    ↓
이동 가능한 다음 노드 찾기
    ↓
방문 여부 확인
    ↓
방문 처리 및 큐에 추가
    ↓
목표 도달 여부 확인
```

결국 BFS에서 중요한 것은
**현재 노드에서 어떤 노드로 이동할 수 있는지 정의하는 것**이다.
