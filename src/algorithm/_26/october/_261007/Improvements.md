# 거스름돈 복기

## 1. 문제 핵심

주어진 화폐를 **무한히 사용**해서 `n`원을 만드는 **조합의 개수**를 구하는 문제.

```java
int n = 5;
int[] money = {1, 2, 5};
```

가능한 조합:

```text
1 + 1 + 1 + 1 + 1
1 + 1 + 1 + 2
1 + 2 + 2
5
```

따라서:

```text
4가지
```

중요한 점은:

```text
1 + 2 + 2
2 + 1 + 2
2 + 2 + 1
```

을 서로 다른 방법으로 세지 않는다는 것.

즉 **순서가 아니라 조합**을 구한다.

---

# 2. 처음 접근

처음에는 각 동전을 몇 개 사용하는지를 저장하는 방법을 생각했다.

```text
{1=5, 2=0, 5=0}
{1=3, 2=1, 5=0}
{1=1, 2=2, 5=0}
{1=0, 2=0, 5=1}
```

즉:

```text
동전 → 사용 개수
```

형태의 `Map`을 생각했다.

---

# 3. 초기 접근의 문제점

각 동전은:

```text
무한히 사용 가능
```

하다.

따라서:

```text
1원을 몇 개 사용할까?
2원을 몇 개 사용할까?
5원을 몇 개 사용할까?
```

를 직접 조합하려고 하면 경우의 수 자체를 생성해야 한다.

문제에서 실제로 필요한 것은:

```text
어떤 조합들이 존재하는가?
```

가 아니라:

```text
조합이 총 몇 개인가?
```

이다.

여기서 저장하려는 상태를 바꿀 필요가 있었다.

---

# 4. 핵심 사고 전환

처음:

```text
어떤 동전을 몇 개 사용했는가?
```

를 저장하려고 했다.

하지만 실제로 필요한 것은:

```text
각 금액을 만들 수 있는 방법의 개수
```

뿐이다.

따라서:

```java
int[] count = new int[n + 1];
```

을 만들고 다음과 같이 의미를 정의한다.

```text
count[i]
=
i원을 만들 수 있는 조합의 개수
```

예를 들어:

```text
count[2] = 2
```

라는 것은:

```text
2원짜리 동전이 2개 있다 ❌

2원을 만드는 방법이 2개 있다 ⭕
```

라는 의미다.

실제로:

```text
1 + 1
2
```

두 가지다.

---

# 5. DP 상태 정의

이번 문제의 가장 중요한 부분.

```java
count[i]
```

의 의미:

```text
현재까지 허용된 화폐들을 사용해서
i원을 만들 수 있는 방법의 수
```

이 정의가 잡히면 이후 구현은 상당히 단순해진다.

---

# 6. 초기값

배열을 생성하면:

```java
int[] count = new int[n + 1];
```

초기 상태는:

```text
[0, 0, 0, 0, 0, 0]
```

이다.

하지만 이 상태에서는:

```java
count[1] += count[0];
```

을 해도:

```text
0 += 0
```

이기 때문에 아무 값도 만들어지지 않는다.

따라서:

```java
count[0] = 1;
```

로 시작한다.

---

# 7. 왜 count[0] = 1인가?

`0원`을 만드는 방법은:

```text
아무 동전도 사용하지 않는다.
```

라는 한 가지 방법이 있다고 정의한다.

```text
{}
```

따라서:

```java
count[0] = 1;
```

이다.

이 값이 이후 모든 조합을 만들어내는 시작점이 된다.

예를 들어 2원짜리 동전을 처리하면:

```java
count[2] += count[0];
```

이고:

```text
count[0] = 1
```

이므로:

```text
아무것도 사용하지 않은 상태
+
2원

→ 2
```

라는 새로운 방법 하나가 생긴다.

---

# 8. 핵심 점화식

현재 사용하고 있는 동전을:

```java
int coin;
```

현재 만들려고 하는 금액을:

```java
int j;
```

라고 하면:

```java
count[j] += count[j - coin];
```

이 된다.

의미는:

```text
(j - coin)원을 만드는 기존의 모든 방법

+

현재 coin 하나

=

j원을 만드는 새로운 방법
```

이다.

---

# 9. 예시

현재 동전:

```text
2원
```

현재 금액:

```text
5원
```

이라면:

```text
5 - 2 = 3
```

따라서:

```java
count[5] += count[3];
```

이다.

만약 3원을 만드는 방법이:

```text
1 + 1 + 1
1 + 2
```

두 가지라면 각각에 `2원`을 추가한다.

```text
1 + 1 + 1 + 2

1 + 2 + 2
```

따라서 5원을 만드는 새로운 방법이 2개 추가된다.

---

# 10. 1원 처리

처음:

```text
금액       0  1  2  3  4  5
count      1  0  0  0  0  0
```

1원을 처리한다.

```java
count[1] += count[0];
count[2] += count[1];
count[3] += count[2];
count[4] += count[3];
count[5] += count[4];
```

결과:

```text
[1, 1, 1, 1, 1, 1]
```

의미:

```text
1원 → 1
2원 → 1+1
3원 → 1+1+1
4원 → 1+1+1+1
5원 → 1+1+1+1+1
```

1원만 사용할 수 있으므로 모든 금액을 만드는 방법은 1개다.

---

# 11. 2원 처리

현재:

```text
[1, 1, 1, 1, 1, 1]
```

2원을 추가한다.

### 2원

```java
count[2] += count[0];
```

```text
1 + 1
2
```

따라서:

```text
count[2] = 2
```

---

### 3원

```java
count[3] += count[1];
```

```text
1 + 1 + 1
1 + 2
```

따라서:

```text
count[3] = 2
```

---

### 4원

여기서 중요한 부분:

```java
count[4] += count[2];
```

이때 `count[2]`는 **이미 2원 동전을 반영해서 갱신된 값**이다.

```text
count[2] = 2
```

따라서:

```text
1 + 1
2
```

각각에 2원을 추가한다.

```text
1 + 1 + 2
2 + 2
```

기존:

```text
1 + 1 + 1 + 1
```

까지 포함해서:

```text
count[4] = 3
```

이 된다.

---

# 12. 왜 작은 금액 → 큰 금액으로 순회하는가?

현재 코드:

```java
for (int j = money[i]; j < count.length; j++) {
    count[j] += count[j - money[i]];
}
```

`j`가 증가한다.

```text
2
3
4
5
...
```

따라서 현재 동전을 사용해서 갱신한 결과를 이후 계산에서 다시 사용할 수 있다.

예를 들어:

```text
coin = 2
```

일 때:

```text
count[2] 갱신
   ↓
count[4]에서 갱신된 count[2] 사용
   ↓
2 + 2 가능
```

즉:

```text
작은 금액 → 큰 금액
```

순회 자체가:

```text
같은 동전을 여러 번 사용할 수 있음
```

이라는 조건을 자연스럽게 처리한다.

---

# 13. 왜 동전을 바깥 반복문으로 두는가?

최종 구조:

```java
for (int coin : money) {

    for (int j = coin; j <= n; j++) {

        count[j] += count[j - coin];
    }
}
```

중요한 순서:

```text
동전
  ↓
금액
```

이다.

이렇게 하면:

```text
1원까지 허용한 조합

↓

1원, 2원까지 허용한 조합

↓

1원, 2원, 5원까지 허용한 조합
```

순서로 확장된다.

따라서:

```text
1 + 2 + 2
```

를 만든 뒤:

```text
2 + 1 + 2
```

같은 순서만 다른 경우를 다시 별개의 조합으로 세지 않는다.

# 15. 알고리즘 분류

## Dynamic Programming (DP)

이번 문제는 DP 문제다.

핵심은:

```text
작은 금액을 만드는 방법의 수를 저장

↓

그 결과를 이용해서
더 큰 금액을 만드는 방법의 수 계산
```

하는 것이다.

점화식:

```java
dp[j] += dp[j - coin];
```

---

# 16. 정수 삼각형 DP와 비교

이전에 풀었던 정수 삼각형에서는:

```text
dp[i][j]

=

(i, j)에 도달할 수 있는
최대 누적값
```

이었다.

점화식은:

```java
dp[i][j]
=
value[i][j]
+
Math.max(
    dp[i - 1][j - 1],
    dp[i - 1][j]
);
```

이번 문제에서는:

```text
dp[i]

=

i원을 만드는
조합의 개수
```

이다.

점화식:

```java
dp[j] += dp[j - coin];
```

코드 모양은 전혀 다르지만 공통점은 같다.

```text
현재 문제를 계산하기 위해
이미 계산한 작은 문제의 결과를 재사용한다.
```

---

# 17. 이번 문제에서 실제로 어려웠던 부분

구현 자체는 어렵지 않았다.

최종 핵심 코드는:

```java
count[0] = 1;

for (int coin : money) {
    for (int j = coin; j <= n; j++) {
        count[j] += count[j - coin];
    }
}
```

정도로 매우 짧다.

어려웠던 것은 이 코드를 작성하는 것이 아니라:

```text
count[i]를 무엇으로 정의할 것인가?
```

였다.

초기에는:

```text
각 동전을 몇 개 사용했는지 저장
```

하려고 했다.

그러나 DP에서는:

```text
구체적인 조합 자체
```

를 저장할 필요가 없었다.

필요한 것은:

```text
그 상태에 도달하는 방법의 개수
```

뿐이었다.

---

# 18. 이번 문제의 핵심 교훈

## DP는 점화식부터 찾는 것이 아니다

처음부터:

```text
점화식이 뭐지?
```

라고 생각하면 어렵다.

먼저:

```text
dp[i]가 무엇을 의미하게 만들 것인가?
```

를 정의한다.

이번 문제에서는:

```text
dp[i]
=
i원을 만들 수 있는 방법의 수
```

였다.

이 정의가 만들어지자:

```text
j원을 만들려면

(j - coin)원을 만드는 방법에
coin을 하나 추가하면 된다.
```

라는 관계가 자연스럽게 나온다.

그리고 그 관계가:

```java
dp[j] += dp[j - coin];
```

이 된다.

# 20. 복잡도

화폐 종류:

```text
M ≤ 100
```

목표 금액:

```text
N ≤ 100,000
```

반복:

```java
for (int coin : money) {
    for (int j = coin; j <= n; j++) {
        ...
    }
}
```

따라서 시간복잡도:

```text
O(M × N)
```

최악의 경우 대략:

```text
100 × 100,000

= 10,000,000
```

약 천만 번 수준이다.

공간복잡도:

```text
O(N)
```

`count` 배열 하나만 사용한다.

# 21. MOD 처리 주의

현재 통과한 코드는:

```java
return count[n] % 1000000007;
```

형태였다.

하지만 일반적으로는 중간 계산에서도 나머지를 적용하는 것이 안전하다.

```java
final int MOD = 1_000_000_007;

count[j] =
    (count[j] + count[j - coin]) % MOD;
```

이유:

```text
중간 결과가 자료형 범위를 넘은 뒤

마지막에 %

→ 이미 overflow가 발생했을 수 있음
```

따라서 경우의 수 문제에서:

```text
정답을 MOD로 나눠라
```

라는 조건이 있으면 보통 계산 과정에서도 MOD를 적용한다.

---

# 22. 최종 정리 코드

```java
public int solution(int n, int[] money) {

    final int MOD = 1_000_000_007;

    int[] count = new int[n + 1];

    count[0] = 1;

    for (int coin : money) {

        for (int amount = coin; amount <= n; amount++) {

            count[amount] =
                (count[amount] + count[amount - coin]) % MOD;
        }
    }

    return count[n];
}
```

# 23. 다음에 비슷한 문제를 만나면

문제에서:

```text
경우의 수

몇 가지 방법

최댓값 / 최솟값

현재 결과를 이전 결과로 계산 가능

같은 작은 문제가 반복됨
```

같은 특징이 보이면 DP 가능성을 생각해본다.

그때 바로 코드를 작성하지 말고:

```text
1. dp[i]는 무슨 뜻인가?

2. dp[i]를 계산하려면
   이전의 어떤 dp 값이 필요한가?

3. 초기값은 무엇인가?

4. 계산 순서는 어떻게 되어야 하는가?
```

부터 정의한다.

이번 문제라면:

```text
1.
dp[i]
= i원을 만드는 조합의 개수


2.
dp[j]
+= dp[j - coin]


3.
dp[0] = 1


4.
동전을 하나씩 허용하면서
coin → n 순서로 금액을 갱신
```

이다.
