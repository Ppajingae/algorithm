# 1일 1코테 개발일지 — 가장 먼 노드

## 문제

**프로그래머스 - 가장 먼 노드**

노드가 `1 ~ n`까지 존재하는 양방향 그래프가 주어진다.

`1번 노드`에서 각 노드까지 **최단경로로 이동했을 때 지나가는 간선의 개수**를 거리라고 할 때, 가장 먼 거리에 존재하는 노드의 개수를 구하는 문제다.

### 제한사항

```text
노드 수
2 ≤ n ≤ 20,000

간선 수
1 ≤ edge.length ≤ 50,000

간선은 양방향
```

예제:

```java
int n = 6;

int[][] edge = {
    {3, 6},
    {4, 3},
    {3, 2},
    {1, 3},
    {1, 2},
    {2, 4},
    {5, 2}
};
```

결과:

```java
3
```

---

# 1. 첫 접근 — 다익스트라를 반대로 사용?

문제를 처음 보고 가장 먼저 떠올린 것은 **다익스트라**였다.

이전에 합승 택시 문제에서 다익스트라를 사용했기 때문에:

```text
1번 노드에서 가장 멀리 떨어진 노드
```

라는 표현을 보고 처음에는 다음과 같이 생각했다.

```text
다익스트라
→ 최단거리 계산

비교를 반대로 하면?
→ 최장거리 계산 가능하지 않을까?
```

그래서 초기 구현에서는:

```java
int INF = Integer.MIN_VALUE;
```

로 거리를 초기화하고:

```java
if (result[next.index] < result[nowVertex] + next.cost) {
    result[next.index] = result[nowVertex] + next.cost;
}
```

처럼 기존 다익스트라의 비교 방향을 반대로 만들려고 했다.

---

# 2. 첫 번째 오해 — 문제는 최장경로를 요구하지 않는다

문제에서 말하는:

```text
"가장 멀리 떨어진 노드"
```

를 처음에는:

```text
1번 → 특정 노드까지 갈 수 있는
가장 긴 경로
```

라고 생각했다.

하지만 실제 의미는 다르다.

문제에서는 명확하게:

```text
최단경로로 이동했을 때
간선의 개수가 가장 많은 노드
```

를 요구한다.

즉 먼저 각 노드까지의 **최단거리**를 구해야 한다.

예를 들어:

```text
dist[1] = 0
dist[2] = 1
dist[3] = 1
dist[4] = 2
dist[5] = 2
dist[6] = 2
```

가 나온다면:

```text
최단거리의 최댓값 = 2
```

이고:

```text
dist == 2인 노드

4
5
6
```

이므로:

```text
answer = 3
```

이다.

### 핵심

```text
❌ 각 노드까지의 최장경로를 구한다.

⭕ 각 노드까지의 최단거리를 구한다.
             ↓
   최단거리들 중 최댓값을 찾는다.
             ↓
   해당 거리를 가진 노드 개수를 센다.
```

문장의 `가장 먼`이라는 표현보다 **`최단경로로 이동했을 때`**라는 조건을 먼저 봐야 했다.

---

# 3. 두 번째 실수 — 노드 번호 차이를 간선 비용으로 생각함

초기 코드에서는 간선을 다음과 같이 저장했다.

```java
for (int[] fare : edge) {
    fareNodes.get(fare[0]).add(
        new Node(fare[0], fare[1] - fare[0])
    );
}
```

예를 들어:

```java
{3, 6}
```

을:

```text
3 → 6

cost = 6 - 3 = 3
```

처럼 처리하려고 했다.

하지만 이 문제에서:

```java
{3, 6}
```

의 의미는 단순히:

```text
3번 노드와 6번 노드가 연결되어 있다.
```

이다.

노드 번호의 차이는 거리와 아무 관계가 없다.

```text
1 ↔ 2
```

도 간선 하나이고:

```text
1 ↔ 10000
```

도 직접 연결되어 있다면 간선 하나다.

따라서 모든 간선의 이동 비용은 동일하게:

```text
1
```

이라고 볼 수 있다.

---

# 4. 양방향 그래프 구성

문제에서 간선이 **양방향**이라고 주어졌다.

따라서:

```java
{3, 6}
```

이 있다면:

```text
3 → 6
6 → 3
```

둘 다 이동 가능해야 한다.

그래프를 다음과 같이 인접 리스트로 구성했다.

```java
ArrayList<ArrayList<Integer>> graph = new ArrayList<>();

for (int i = 0; i <= n; i++) {
    graph.add(new ArrayList<>());
}

for (int[] e : edge) {
    int a = e[0];
    int b = e[1];

    graph.get(a).add(b);
    graph.get(b).add(a);
}
```

예제에서는 대략:

```text
1 → [3, 2]
2 → [3, 1, 4, 5]
3 → [6, 4, 2, 1]
4 → [3, 2]
5 → [2]
6 → [3]
```

형태가 된다.

---

# 5. BFS를 선택

DFS와 마찬가지로 BFS 역시 이전까지는 **이름만 알고 있었고 실제 알고리즘의 동작 방식이나 구현 방법은 알지 못했다.**

이번 문제를 풀면서 BFS 알고리즘을 따로 찾아봤고 실제 코드에 처음 적용했다.

BFS는:

```text
Breadth-First Search
너비 우선 탐색
```

이다.

핵심은 현재 위치에서 가까운 노드부터 순서대로 방문한다는 것이다.

```text
거리 0

        1

거리 1

      2   3

거리 2

    4   5   6

거리 3

       ...
```

탐색 순서는:

```text
거리 0
↓
거리 1
↓
거리 2
↓
거리 3
↓
...
```

형태가 된다.

---

# 6. 왜 이 문제에서 BFS를 사용할 수 있는가?

이 문제의 모든 간선은 동일한 비용을 가진다.

```text
간선 하나 이동
= 거리 +1
```

따라서 BFS를 사용하면 시작점에서 가까운 노드부터 방문한다.

예를 들어:

```text
1
├── 2
│   ├── 4
│   └── 5
└── 3
    └── 6
```

라면:

```text
1
거리 0

2, 3
거리 1

4, 5, 6
거리 2
```

순서로 방문한다.

따라서 어떤 노드를 **처음 방문했을 때의 거리**가 그 노드까지의 최단거리가 된다.

### 기억할 패턴

```text
가중치가 없는 그래프
또는
모든 간선의 비용이 동일한 그래프

+

최단거리

→ BFS를 우선 생각해볼 수 있다.
```

반대로 간선마다 비용이 다르다면:

```text
A → B : 10
A → C : 1
C → B : 2
```

단순히 간선 개수만으로 최단거리를 판단할 수 없기 때문에 BFS만으로 처리할 수 없다.

이런 경우에는 다익스트라 같은 가중치 최단경로 알고리즘을 고려한다.

---

# 7. BFS에서 Queue를 사용하는 이유

BFS에서는 `Queue`를 사용한다.

Queue는:

```text
FIFO
First In First Out

먼저 들어온 것이 먼저 나온다.
```

는 구조다.

이번 구현에서는:

```java
Queue<int[]> q = new ArrayDeque<>();
```

를 사용했다.

Queue에:

```java
new int[]{노드 번호, 거리}
```

를 저장했다.

시작은:

```java
q.offer(new int[]{1, 0});
```

이다.

즉:

```text
1번 노드
거리 0
```

에서 탐색을 시작한다.

---

# 8. BFS의 기본 구조

이번 문제에서 직접 사용한 BFS의 핵심 형태는 다음과 같다.

```java
Queue<int[]> q = new ArrayDeque<>();

q.offer(new int[]{1, 0});
visited[1] = true;

while (!q.isEmpty()) {

    int[] poll = q.poll();

    for (int search : graph.get(poll[0])) {

        if (!visited[search]) {

            q.offer(new int[]{
                search,
                poll[1] + 1
            });

            visited[search] = true;
        }
    }
}
```

이 구조를 일반화하면:

```text
1. 시작 노드를 Queue에 넣는다.

2. 시작 노드를 방문 처리한다.

3. Queue에서 노드를 하나 꺼낸다.

4. 현재 노드와 연결된 노드를 확인한다.

5. 아직 방문하지 않았다면
   Queue에 넣는다.

6. 방문 처리한다.

7. Queue가 빌 때까지 반복한다.
```

이다.

---

# 9. visited가 필요한 이유

그래프에는 다음과 같은 구조가 있을 수 있다.

```text
1 ─ 2
│   │
3 ─ 4
```

`visited`가 없다면:

```text
1 → 2 → 4 → 3 → 1 → 2 → ...
```

처럼 이미 방문한 노드를 계속 다시 방문할 수 있다.

따라서:

```java
boolean[] visited = new boolean[n + 1];
```

를 사용한다.

그리고 Queue에 넣을 때 바로:

```java
visited[search] = true;
```

로 처리했다.

```java
if (!visited[search]) {

    q.offer(...);

    visited[search] = true;
}
```

이렇게 하면 같은 노드가 Queue에 여러 번 들어가는 것을 방지할 수 있다.

---

# 10. 중간 구현에서의 실수

처음 BFS를 구현했을 때 다음 조건을 넣었다.

```java
if (poll[0] == j) {
    return poll[1];
}
```

여기서 `j`에는 `n`을 전달했다.

즉:

```text
n번 노드를 발견하면 탐색 종료
```

라는 의미였다.

하지만:

```text
노드 번호가 크다
=
시작점에서 멀리 있다
```

는 관계는 없다.

예를 들어:

```text
1 ─ 6

1 ─ 2 ─ 3 ─ 4 ─ 5
```

라면:

```text
dist[6] = 1
dist[5] = 4
```

이다.

`n = 6`이라고 해서 6번 노드가 가장 먼 노드인 것은 아니다.

따라서 가장 먼 거리를 찾으려면 BFS를 끝까지 수행해야 한다.

---

# 11. 거리별 개수를 저장하려고 했던 접근

중간에는 다음과 같이 거리별 노드 개수를 배열에 저장하려고 했다.

```java
result[poll[1]]++;
```

예제라면:

```text
result[0] = 1
result[1] = 2
result[2] = 3
```

형태가 된다.

이 방법도 가능하다.

하지만 최종적으로 생각해보면 문제에서 필요한 것은 모든 거리별 개수가 아니다.

필요한 것은:

```text
현재 가장 먼 거리

+

그 거리에 존재하는 노드 개수
```

두 개뿐이다.

따라서 배열 전체를 저장하지 않고:

```java
int farthest = 0;
int count = 0;
```

만 사용했다.

이 역시 이전 문제들에서 반복해서 나온:

```text
"최종 결과에 필요한 상태만 저장한다."
```

는 패턴과 연결된다.

# 12. 최종 구현

```java
public int solution(int n, int[][] edge) {

    ArrayList<ArrayList<Integer>> graph = new ArrayList<>();

    for (int i = 0; i <= n; i++) {
        graph.add(new ArrayList<>());
    }

    for (int[] e : edge) {
        int a = e[0];
        int b = e[1];

        graph.get(a).add(b);
        graph.get(b).add(a);
    }

    boolean[] visited = new boolean[n + 1];

    return bfs(visited, graph);
}

private int bfs(
        boolean[] visited,
        ArrayList<ArrayList<Integer>> list
) {

    Queue<int[]> q = new ArrayDeque<>();

    int farthest = 0;
    int count = 0;

    q.offer(new int[]{1, 0});

    visited[1] = true;

    while (!q.isEmpty()) {

        int[] poll = q.poll();

        for (int search : list.get(poll[0])) {

            if (!visited[search]) {

                q.offer(new int[]{
                    search,
                    poll[1] + 1
                });

                visited[search] = true;
            }
        }

        if (farthest < poll[1]) {
            farthest = poll[1];
            count = 0;
        }

        count++;
    }

    return count;
}
```

---

# 13. farthest / count가 동작하는 이유

BFS에서는 Queue에서 노드가 거리 순서대로 나온다.

예제라면:

```text
node    distance

1       0

3       1
2       1

6       2
4       2
5       2
```

거리만 보면:

```text
0
1
1
2
2
2
```

처럼 나온다.

따라서:

```java
if (farthest < poll[1]) {
    farthest = poll[1];
    count = 0;
}

count++;
```

가 가능하다.

실제로 따라가 보면:

```text
distance = 0

farthest = 0
count = 1
```

다음:

```text
distance = 1

새로운 최대거리

farthest = 1
count = 0

count++

count = 1
```

다음 노드:

```text
distance = 1

farthest와 동일

count = 2
```

다음:

```text
distance = 2

새로운 최대거리

farthest = 2
count = 0

count++

count = 1
```

이후:

```text
distance = 2
count = 2

distance = 2
count = 3
```

최종적으로:

```text
return 3
```

이 된다.

# 14. DFS와 BFS

전력망 문제에서는 DFS를 처음 실제로 접했고, 이번에는 BFS를 처음 실제로 적용했다.

둘 다 그래프를 탐색하는 방법이지만 탐색 순서가 다르다.

## DFS

```text
Depth-First Search
깊이 우선 탐색
```

한 방향으로 최대한 깊게 들어간다.

```text
1
│
2
│
4
│
7
```

이후 돌아와서 다른 경로를 탐색한다.

대표적인 구현 방법:

```text
재귀
또는
Stack
```

---

## BFS

```text
Breadth-First Search
너비 우선 탐색
```

현재 위치에서 가까운 노드를 먼저 모두 방문한다.

```text
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

탐색 순서는:

```text
1

2 3

4 5 6 7
```

대표적인 구현 방법:

```text
Queue
```

---

# 15. DFS와 BFS를 어떻게 구분할 것인가

단순하게:

```text
그래프 문제
→ 무조건 DFS

그래프 문제
→ 무조건 BFS
```

로 외우는 것은 좋지 않다.

문제에서 필요한 정보가 무엇인지 먼저 봐야 한다.

예를 들어:

```text
연결된 모든 노드를 방문하고 싶다.
```

라면 DFS와 BFS 모두 가능할 수 있다.

반면:

```text
가중치 없는 그래프에서
시작점으로부터 최소 몇 개의 간선을 지나야 하는가?
```

라면 BFS의:

```text
거리 순서대로 탐색한다.
```

는 특성이 직접적으로 도움이 된다.

### 이번 문제

```text
1번에서 각 노드까지 최단거리 필요
+
모든 간선의 비용 동일
```

따라서:

```text
BFS
```

가 자연스럽게 연결된다.

---

# 16. 다익스트라와 BFS의 관계

처음 다익스트라를 생각한 것 자체가 완전히 동떨어진 접근은 아니었다.

둘 다 시작점에서 다른 노드까지의 **최단거리**를 구하는 데 사용할 수 있다.

다만 차이가 있다.

### BFS

```text
모든 간선 비용이 동일

예:
1, 1, 1, 1 ...
```

이라면 Queue를 이용해서 거리 순서대로 탐색할 수 있다.

### 다익스트라

```text
간선마다 비용이 다름

예:
A → B = 10
A → C = 3
C → B = 2
```

같은 경우에는 단순 방문 순서만으로 최단거리를 결정할 수 없다.

그래서 우선순위 큐 등을 사용해:

```text
현재까지 비용이 가장 작은 노드
```

를 우선적으로 처리한다.

### 기억

```text
가중치 없는 그래프 최단거리
→ BFS 우선 고려

양수 가중치 그래프 최단거리
→ 다익스트라 고려
```

# 17. 시간 복잡도

그래프의 노드 수를:

```text
V
```

간선 수를:

```text
E
```

라고 하자.

인접 리스트 생성:

```text
O(E)
```

BFS에서는 각 노드를 최대 한 번 방문한다.

```text
O(V)
```

양방향 간선을 인접 리스트에 두 번 저장하므로 연결 관계 확인은:

```text
2E
```

정도다.

Big-O에서는:

```text
O(V + E)
```

이다.

이번 문제 최대 입력은:

```text
V = 20,000
E = 50,000
```

이므로 대략적인 탐색 규모는:

```text
노드 방문
20,000

양방향 간선 확인
100,000

약 120,000 수준
```

으로 충분히 작다.

---

# 18. 공간 복잡도

인접 리스트:

```text
O(V + E)
```

visited:

```text
O(V)
```

Queue:

```text
최악 O(V)
```

따라서 전체 추가 공간 복잡도는:

```text
O(V + E)
```

이다.

# 19. 이번 문제에서 잘한 점

## 1. 그래프를 인접 리스트로 표현

처음에는 다익스트라용 `Node` 객체를 사용했지만 BFS로 전환하면서:

```java
ArrayList<ArrayList<Integer>>
```

로 단순화했다.

간선의 비용이 없기 때문에:

```text
현재 노드와 연결된 노드 번호
```

만 저장하면 충분했다.

---

## 2. 양방향 간선을 제대로 구성

```java
graph.get(a).add(b);
graph.get(b).add(a);
```

로 양방향 관계를 정확하게 표현했다.

---

## 3. BFS를 찾아본 뒤 직접 구현

BFS의 이름만 알고 있었던 상태에서 동작 방식을 찾아본 뒤:

```text
Queue
visited
인접 리스트
거리
```

를 조합해서 직접 구현했다.

특히 단순히 BFS 코드를 작성한 것에서 끝나지 않고:

```java
new int[]{node, distance}
```

형태로 현재 거리까지 Queue에 넣어서 문제에서 필요한 정보를 직접 관리했다.

---

## 4. 거리별 배열을 최종적으로 제거

중간에는:

```java
result[distance]++;
```

로 모든 거리의 개수를 저장하려고 했다.

하지만 최종적으로:

```java
int farthest;
int count;
```

두 값만 있으면 된다는 구조로 줄였다.

이는:

```text
"내가 저장하고 있는 값이 최종 결과에 정말 필요한가?"
```

를 생각한 좋은 변화였다.

# 20. 개선할 점

## 1. 문제에서 사용하는 용어를 정확하게 분해하기

이번에 가장 먼저 잘못 잡은 부분은:

```text
가장 먼 노드
→ 최장경로
```

였다.

하지만 문제에는:

```text
최단경로로 이동했을 때
```

라는 조건이 있었다.

앞으로는 문제에서:

```text
최소
최대
최단
최장
가장 가까운
가장 먼
```

같은 표현이 나오면 한 문장으로 다시 써보는 것이 좋다.

이번 문제라면:

```text
각 노드까지의 최단거리를 구하고,
그 최단거리 중 가장 큰 값을 가진 노드의 개수를 구한다.
```

이 한 문장으로 정리할 수 있다.

---

## 2. 노드 번호와 비용을 구분하기

```java
fare[1] - fare[0]
```

처럼 노드 번호를 거리 계산에 사용했지만:

```text
노드 번호 = 식별자
```

일 뿐이다.

노드 번호 자체에는 일반적으로 거리나 순서의 의미가 없다.

```text
1 ↔ 10000
```

도 직접 연결되어 있으면 거리는 간선 하나다.

앞으로 그래프 문제에서는:

```text
노드 번호
간선
간선 비용
```

을 별개의 정보로 생각한다.

---

## 3. 알고리즘 이름보다 특성을 연결하기

이번까지는:

```text
BFS라는 이름을 알고 있다.
DFS라는 이름을 알고 있다.
```

정도였다.

앞으로는 이름보다 다음 특징을 기억하는 것이 중요하다.

```text
BFS
→ Queue
→ 가까운 노드부터
→ 레벨 단위 탐색
→ 가중치 없는 그래프 최단거리

DFS
→ Stack / 재귀
→ 한 방향으로 깊게
→ 연결된 영역 탐색
```

문제를 봤을 때:

```text
"이거 BFS 문제인가?"
```

부터 생각하기보다:

```text
"시작점에서 가까운 순서로 방문하면 문제가 해결되는가?"
```

를 먼저 생각하면 알고리즘을 스스로 선택하기 쉬워진다.

# 21. 이번 문제의 사고 과정

전체 과정을 정리하면:

```text
문제 확인

↓

"가장 먼 노드"
→ 다익스트라를 반대로 하면 최장거리?

↓

문제 다시 분석

"최단경로로 이동했을 때 가장 먼 노드"

↓

BFS를 찾아봄

↓

Queue + visited를 이용한 BFS 구현

↓

각 노드까지의 거리를 Queue에 함께 저장

↓

처음에는 n번 노드에 도착하면 종료

↓

노드 번호와 거리는 관계없음을 확인

↓

BFS 전체 탐색

↓

거리별 개수를 배열에 저장

↓

모든 거리별 정보는 필요하지 않음을 확인

↓

farthest + count만 유지

↓

통과
```

# 22. 오늘의 핵심 패턴

앞으로 다음 조건이 나오면 BFS를 떠올려본다.

```text
그래프 / 격자
+
한 지점에서 출발
+
최소 이동 횟수 / 최소 간선 개수
+
모든 이동 비용이 동일
```

그러면:

```text
BFS
```

를 후보로 생각한다.

특히:

```text
최소 몇 번 이동?
최소 몇 단계?
최단 간선 수?
가장 가까운?
몇 번째 단계에서 도착?
```

같은 표현을 주의해서 본다.

# 23. 이전 전력망 문제와 연결

전력망 문제에서는 DFS를 처음 실제로 접했다.

```text
전선 하나 제거
↓
한쪽 네트워크에서
연결된 노드가 몇 개인지 전부 탐색

→ DFS
```

이번 문제에서는:

```text
1번 노드에서
각 노드까지 최소 몇 개의 간선을 지나야 하는지 계산

→ BFS
```

두 문제 모두 그래프 탐색이지만 **필요한 정보가 달랐다.**

```text
전력망
→ 연결된 노드를 모두 방문하고 개수 계산

가장 먼 노드
→ 시작점으로부터 거리 순서대로 탐색
```

그래서 전자는 DFS로 접근했고 이번에는 BFS를 사용했다.

# 24. 최종 정리

이번 문제에서 새로 가져갈 것은 단순히:

```text
BFS 코드를 외웠다.
```

가 아니다.

다음 관계를 기억하는 것이 중요하다.

```text
그래프
    ↓
무엇을 구해야 하는가?
    ↓
시작점에서 각 노드까지 최소 간선 수
    ↓
간선 비용이 모두 동일한가?
    ↓
YES
    ↓
BFS
```

그리고 BFS의 기본 구조:

```text
Queue 생성

↓

시작점 삽입 + 방문 처리

↓

Queue에서 하나 꺼냄

↓

연결된 노드 확인

↓

방문하지 않았다면
Queue에 삽입 + 방문 처리

↓

Queue가 빌 때까지 반복
```

이 구조를 이번에 처음 실제 문제에서 사용했다.
